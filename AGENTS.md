# Repository Guidelines

Vibeswap is a Vite + React + TypeScript DEX/arcade dApp targeting the LitVM LiteForge chain (chain ID 4441), with Solidity contracts deployed via `viem`.

## Project Structure & Module Organization

- `src/` — React app. `src/components/` holds UI components; `src/contracts/` holds per-contract ABI files (`GM.ts`, `Swap.ts`, `VibeGame.ts`, `vbUSDC.ts`) plus `deployments.ts`, the single source of truth for deployed addresses.
- `contracts/` — Solidity sources (`.sol`), one file per contract.
- `scripts/` — Node deployment/reserve scripts (`deploy-*.js`, `check-reserves.js`).
- `docs/` — GitBook documentation.
- `public/` — static assets (favicons).

## Build, Test, and Development Commands

- `npm install` — install dependencies.
- `npm run dev` — start the Vite dev server (http://localhost:5173).
- `npm run build` — type-check and produce a production bundle in `dist/`.
- `npm run preview` — serve the production build locally.
- `npm run deploy:gm` / `deploy:game` / `deploy:swap` — compile the contract with `solc` and deploy it, writing to `deployments-*.json` and updating `src/contracts/deployments.ts`.
- `npm run monitor:reserves` — print swap pool reserves and rate.

## Coding Style & Naming Conventions

- TypeScript/JavaScript: 2-space indentation, single quotes, trailing commas, no semicolons.
- Components and contracts use `PascalCase` filenames (`GMTracker.tsx`, `Swap.sol`); ABI files mirror the contract name.
- CSS classes use `kebab-case`.
- Solidity: 4-space indentation, `pragma solidity ^0.8.26;`, private/internal functions prefixed with `_`.
- No formatter or linter is configured; match surrounding file style when editing.

## Testing Guidelines

There is no test suite. Before changing logic, run `npm run build` to verify TypeScript compiles, and test flows manually in the dev server against LiteForge.

## Commit & Pull Request Guidelines

Commit history is short and descriptive (e.g., "Alpha version 0.2.2", "Docs update") rather than conventional-commit formatted. Keep commits focused and imperative.

Pull requests should include a description of what changed and why, and note any new contract deployments with the resulting addresses.

## Security & Configuration Tips

- Never commit `.env` or private keys; copy `.env.example` to `.env` for local secrets.
- `src/contracts/deployments.ts` is regenerated by deploy scripts — verify addresses after any deployment.
- Keep treasury/deployer private keys out of git, and keep swap liquidity funded.
